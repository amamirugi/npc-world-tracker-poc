# v0.4 검증과 조작

현재 v0.4 구현은 검토 브랜치용이다. 실제 RisuAI + 보조 모델 + Hayaku 조합의 인수 검증 전에는 main 업데이트 배포 완료로 보지 않는다.

## 실행한 검증

- `node --check npc-world-tracker-poc.js`
- `node --test tests/tracker.test.cjs`: Node 내장 VM에서 실제 플러그인 함수를 로드하고 RisuAI 저장소·요청 API를 모의한다.
- Sanctum `scripts/check-text-integrity.mjs --repo <checkout>`와 full diff 검토.

모의 검증은 projection 필드 경계, arrival 필수 근거, empty injection, soft TTL/revision, retry/reload/reroll, stale write/auxiliary epoch, scheduler 선택·배치·원자적 실패, legacy migration, queue 보존, UI markup/핸들러 연결을 확인한다. 의미 판단의 정확도나 실제 브라우저 레이아웃까지 증명하지는 않는다.

## 설치 후 관제

1. 설치된 플러그인의 🧭 NPC World Tracker 버튼 또는 설정에서 대시보드를 연다.
2. 기존 lore 연결과 보조 모델 설정을 확인한다. 보조모델 연결 기본값은 `RisuAI에 설정된 보조모델`이다. RisuAI에서 보조모델을 설정하면 tracker에 별도 키·endpoint·모델명을 입력하지 않아도 된다. 기존 직접 API를 쓰려면 `직접 설정 API`를 선택해 저장한다. 생성 토큰·온도 설정은 RisuAI를 따르고, tracker의 배치 예산은 평가 대상 묶음 크기에만 적용된다. v0.4는 기존 v0.3.3 상태를 별도 v4 키로 이전하고, 이전 키는 수정하지 않는다.
3. 각 NPC의 attention 등급·압력·제약·다음 평가 시점과 최근 projection 문자 수를 확인한다.
4. `추적만 다시 실행`은 최신 응답의 같은 작중 시점을 재분석한다. 시간을 추가 진행시키지 않는다.
5. `추적 비활성`은 NPC의 자동 평가를 중단하고 `추적 재개`로 복귀한다. 이미 성립한 사건을 소급 취소하는 버튼은 아니다.
6. 주입 주기·major threshold·전체 상태 강제 주입은 제거했다. 전달할 신호가 없으면 주입 0자다. Warm 순환 평가 수는 초기 4명이다.

## main 반영 전 실제 RisuAI 인수 항목

- RisuAI 보조모델 연결에서 실제 선택된 모델, 비스트리밍/스트리밍 JSON 응답, coverage repair와 다른 플러그인 hook 영향을 확인한다. 보조모델 설정이 없거나 API가 미지원일 때 오류를 확인하고 직접 API로 자동 전환되지 않는지 본다. 로컬 timeout은 늦은 결과 적용을 막지만 host 요청 취소를 보장하지 않는다.
- 복제한 테스트 채팅에서 시작한다. RisuAI 버전과 보조 모델명을 기록한다.
- 원거리 NPC 행동 완료가 hard로 새지 않는지, 유효한 soft가 메인의 선택지로 작동하는지 확인한다.
- 연락 도착과 읽음·인지가 구분되는지 확인한다. 소문 내용 자체가 정사로 승격되면 실패다.
- 보조 응답의 arrived/route/evidence/exposure 값이 실제 인과 근거와 맞는지 본다. 필드 존재 검사는 의미적 진실을 증명하지 않는다.
- 요청 실패·새로고침·reroll 및 최근 5개 이내 되돌리기 후 중복/유실을 확인한다.
- 삭제·편집·채팅 복제·채팅 전환에서 실제 hook 시점과 chat id/원문 변화를 확인한다.
- 보조 호출 중 다음 응답을 요청해 오래된 결과가 적용되지 않는지, 이어진 평가가 최신 장면을 따라잡는지 확인한다.
- 20–40 NPC에서 호출 수·입출력 토큰·지연을 기록한다. Hot 집중은 등록 제한 없이 배치로 처리하므로 호출량이 증가할 수 있다.
- Hayaku를 함께 켜고 main 요청 원문에서 tracker의 전체 lore/census/장기기억 재주입이 없는지 확인한다.

## 알려진 범위와 한계

- 재평가 턴 수는 작중 시간 타이머가 아니다. 자연어 wake는 휴리스틱 후보 신호이며 의미는 보조 모델이 확인한다. 조건이 있는 Cold에는 재검토 기한이 있다.
- 롤백은 최근 5개 요청에 한정된다. 복구 불가능한 편집 감지 시 주입·추적을 보류하고 대시보드에 표시한다. 이 경우 기존 `추적 상태 초기화`는 NPC 등록도 지우므로 확인창 내용을 읽고 다시 연결해야 한다.
- 원문 user 메시지와 요청 user 메시지가 일치할 때 전체 원문 prefix hash를 추가 검증한다. 호스트 변환으로 매칭할 수 없으면 최근 transcript guard만 적용되며, 오래된 편집을 전부 탐지한다고 보장하지 않는다.
- 동일한 mode만 제공하는 before/after hook에서 동시에 여러 main 요청이나 채팅을 전환하는 경우의 정확한 요청 상관관계는 호스트 인수 대상이다.
- 저장 쓰기 직렬화와 revision 검사는 한 플러그인 인스턴스 안의 경쟁을 막는다. 여러 브라우저/기기가 같은 저장소에 동시에 쓰는 분산 잠금은 아니다.
- v0.3.3 롤백은 이전 JS와 보존된 이전 상태를 사용한다. v0.4에서 진행한 상태를 v0.3.3으로 역변환하지 않는다. 설정 키는 공유하므로 구 버전으로 돌아가면 제거된 설정은 구 버전 기본값으로 복원된다.
- 보조 모델의 prose 의미·정보 최소화는 prompt 계약과 실측 검토 대상이다. 모든 비밀 배경의 의미적 유출을 로컬 스키마 검사만으로 보장하지 않는다.
